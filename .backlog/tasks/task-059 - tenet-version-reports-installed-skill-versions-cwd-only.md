## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
tenet --version currently prints only the global binary version. Inside a Tenet project, the installed skill copies (.claude/skills/tenet/SKILL.md and .agents/skills/tenet/SKILL.md) carry a 'Generated by Tenet <version> from ...' stamp written by tenet init — the only record of which version last refreshed them. After npm upgrade without tenet init --upgrade, skills silently lag the binary. tenet --version should report the installed skill versions alongside the CLI version so the drift is visible at version-check time. Scope: CLI flag output only; lookup in cwd only, no parent walk-up (explicit user decision, 2026-11-23); strictly read-only, never fails. The agent-boot-time mismatch warning stays in TASK-042, which shares the same stamp mechanism.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
IMPLEMENTATION NOTES (2026-11-23):

Mechanism — commander custom --version: verified against installed commander v14.0.3 source that .version() registers an option:version listener that prints the bare version and exits (node_modules/commander/lib/command.js:2204). Listeners fire in registration order, so a listener registered BEFORE .version() runs first; ours prints formatVersionReport() and process.exit(0) before the built-in can. Flags stay the default -V, --version; the description was updated to mention the skills report. No commander API fight, 6-line change in src/cli/index.ts.

Version source: the only installed-version record is the stamp comment tenet init injects after each SKILL.md's frontmatter (src/cli/init.ts:546 'Generated by Tenet <v> from ...'). readSkillStampVersion parses it with a regex; return contract: undefined = file missing, null = present but stamp missing (hand-edited or pre-stamp install), string = stamped version. No version stamp exists in .tenet/.state/config.json, the DB (schema number only), or .mcp.json — so the SKILL.md grep was the right instinct.

Output states (all covered by tests): bare version outside projects (byte-identical to previous output); 'tenet <v>' + one skills line per distinct stamped version; grouped locations per version, SKILL.md filename trimmed from the displayed path; hints: up to date / stale + tenet init --upgrade / newer than the global CLI / version stamp missing. cwd with .tenet but no copies gets a reinstall hint (the tenet source repo itself is this state — dogfooding .tenet/ without installed skill copies).

compareCalVer is a local component-wise numeric compare (CalVer YY.MM.PATCH, missing components = 0). update-checker's isNewer is module-private and npm-shaped; not reused.

Fail-open design: the whole report is wrapped so any read/parse error degrades to the bare version, exit 0. Lookup is cwd-only per user decision — no fs walking, no new helper.

VALIDATION: 12 new unit tests in src/cli/version.test.ts (all output states + stamp parser + CalVer compare); make check green: clean+build+typecheck+lint+461 tests/33 files. CLI smoke-tested against the built dist binary in temp projects for all four real states plus --help description.
